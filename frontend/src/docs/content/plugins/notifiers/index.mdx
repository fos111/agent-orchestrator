---
title: Notifications
description: Durable in-app notifications and Electron toasts built into AO.
---

Notifications are a daemon and desktop capability, not a configurable plugin slot. Orchestrator currently persists notifications for these lifecycle events:

- a session needs input;
- a session's runtime crashed;
- a pull request is ready to merge;
- a pull request was merged;
- a pull request closed without merging.

A crash alert is limited to a runtime that AO confirmed died on its own. Explicit kills, normal agent exits, and launch failures do not produce a crash notification. Crash alerts use generic copy and do not include logs, prompts, paths, environment values, or provider data.

In the desktop app, the notification center shows a newest-first feed and loads older alerts as you scroll. Opening it marks loaded unread alerts as read; click an alert to open its session or pull request. New alerts can also appear as desktop toasts while the app is running.

Slack, Discord, generic webhook, OpenClaw, and standalone desktop notifier configuration from the legacy TypeScript release are not supported in the rewrite.

See [notification center](/plugins/notifiers/dashboard) for controls and mobile push details.
